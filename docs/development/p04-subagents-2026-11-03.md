# P04 — One child, same provider and model

Date: 2026-11-03. Status: COMPLETE for this local harness interoperability
subset; stop for review before committing P04 or starting P05.

P03 was committed first as `b7bd982` in Protoverta. Consumer baselines remain
CodexApter `5c06c60` and ClaudApter `9ca4822`, on `integration/protoverta`.
Nothing was pushed, merged or released. No real provider was called.

## Acceptance contract

One child runs within its parent session, using the same selected provider and
exact model ID. The child must make its own inference requests, execute a
harmless client tool, replay its result with the original call ID, finish, and
return its result to the parent. A textual claim that an agent ran is not pass.

The fixture runs real Codex **0.166.0** and Claude Code **2.1.308** through the
actual source launchers. Only the model responses are scripted, on loopback.
Homes, config, credentials, session state, catalog, files and workspaces are
temporary. Provider authentication uses a fixed fake key; the local fixture
requires that credential. Every inference request checks the exact selected
model and expected upstream endpoint. No sandbox or user permissions are changed.

## Final real-client matrix

All rows passed on the final code, with verified lifecycle completion.

| Client | Harness input → upstream | Inference requests | Child tool |
|---|---|---:|---|
| Codex | Responses → Responses (native control) | 5 | Audited local stdio MCP read |
| Codex | Responses → Chat Completions | 5 | Audited local stdio MCP read |
| Codex | Responses → Messages | 5 | Audited local stdio MCP read |
| Claude | Messages → Messages (native control) | 4 | Built-in Read |
| Claude | Messages → Chat Completions | 4 | Built-in Read |
| Claude | Messages → Responses | 4 | Built-in Read |

Codex sequence: parent spawn request → parent receives real child ID and calls
wait → child requests a read → child replays `p04_read` → parent receives
`p04_wait` and completes. The CLI's completed collaboration events must identify
the same single child in spawn and wait, with completed status and the child's
verified final value. The MCP process separately audits exactly one real call;
merely emitting a tool call or the expected value does not satisfy that check.

Claude sequence: parent invokes Agent → child requests Read → child replays
`p04_read` → parent replays `p04_spawn` and completes. The CLI must report one
spawned, one completed and zero failed subagents, without permission denials.
The scripted Agent call explicitly sets `run_in_background=false`.

For translated Codex routes, Responses namespaces are flattened with the
existing request-scoped aliases and restored on the return path. The fixture
uses the exact advertised aliases for `multi_agent_v1` and `mcp__p04`, not fuzzy
name matching. Call IDs remain unchanged. Core reasoning conversion was not
modified or relaxed; these fixtures return no reasoning.

## Codex opt-in

The normal conservative defaults remain unchanged. Translated subagent support
is enabled only when `CODEX_CA_ENABLE_SUBAGENTS=1` is set for the launcher process,
and all of these checks pass before launching Codex:

- Exact CLI version 0.166.0.
- Provider `agent_models = { policy = "selected" }`.
- An exact selected-model entry in `CODEX_CA_MODEL_CATALOG`.
- Explicit `supports_search_tool=false`, without a code-only tool mode.

The verified local-tools combination needs **both** `features.multi_agent=true`
and `agents.enabled=true`. The opt-in also caps open child threads at one.
Leaving the legacy feature false hid the spawn tools in the negative control.
Unknown versions, missing/unknown catalog entries, other model policies and
unsupported tool modes fail with a clear launcher error. No catalog metadata
is silently invented for real provider models. Native Responses retains the
harness's own agent settings.

This selects same-model **defaults**; custom agent files and explicit spawn
overrides keep their ordinary harness precedence. They are not forcibly
rewritten or certified by this test. Concurrent and different-model operation
requires P05/P06. Generic user-supplied CLI overrides can leave the documented
subset; the launcher does not claim to police arbitrary harness arguments.

ClaudApter needs no new enable flag: its existing selected-model policy already
propagates to the child. Its README now states the tested foreground subset.
Codex's optional uninstall environment reset includes the new adapter variable;
provider keys and shared Codex/Claude variables remain protected.

## Findings during fixture development

- Codex accepted unknown model metadata for a parent but rejected spawning that
  model. An explicit isolated catalog resolved the fixture prerequisite. The
  fixture clones bundled gpt-5.5 metadata under a synthetic model ID; this does
  not certify or rename any real provider model.
- Deferred tool search added a tool with an `execution` field and hid eagerly
  advertised spawn tools. That route still rejects; no field was stripped to
  force acceptance. P11 owns deferred-tool lifecycle coverage.
- A shell read was rejected by this test environment's policy. The final Codex
  fixture instead uses an explicitly configured stdio MCP tool that reads only
  its fixed temporary fixture file. Shell availability is not certified.
- Intermediate harness errors included case-sensitive Agent lookup and missing
  MCP namespace alias matching. These were fixture bugs, corrected before the
  final six-row matrix. Failed cases were not counted as passes.

## Reproduce

From Protoverta, using an isolated Python environment with matching editable
consumer source and the documented real CLI versions:

```powershell
& $PreviewPython scripts/smoke_subagents.py --client codex --upstream chat --adapter-source ../free-codex-cli --report NEW_CODEX_REPORT.json
& $PreviewPython scripts/smoke_subagents.py --client claude --upstream responses --adapter-source ../free-claude-cli --report NEW_CLAUDE_REPORT.json
```

Repeat with upstream `responses`, `chat` and `messages` for each client. The
script creates temporary config and sets the scoped opt-in itself; do not set
real provider variables. `--inspect-only` captures advertised schema and is
explicitly not a subagent lifecycle pass. CLI execution is bounded to 45 seconds
and its own process tree is cleaned on timeout. Reports contain synthetic data
and temporary paths; do not use this fixture to capture a real user session.
